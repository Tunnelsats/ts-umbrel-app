# Project Rules & Customizations: TunnelSats Umbrel App

## Security Standards
- **Zero Vulnerabilities Policy**: Never ignore, bypass, or downplay security vulnerabilities flagged by package managers or security scanners. Always resolve all vulnerabilities using updates, patches, or overrides before considering any task complete.

## CI/CD Standards
- **Zero Broken CI Builds Policy**: Never merge any Pull Request or push changes to `master` without verifying that all GitHub Actions CI status checks pass cleanly. Wait for workflow runs to complete with 100% success.

## Privacy & Dataplane Engineering Standards
- **Zero Mocked Dataplanes Policy**: Never write dummy, stub, or placeholder functions that return `True` or log success without executing real system actions (e.g. `print("Gateway active"); return True`). Never paper over missing platform features. If a platform capability does not exist or cannot be achieved via the SDK, explicitly document the limitation and halt/escalate the task.
- **Fail-Closed Verification Policy**: Privacy, routing, and security diagnostics must test real kernel interfaces (`wg show`, `ip rule`, `ip route`, external egress probes). Probing a website over clearnet or checking file existence is strictly prohibited as proof of a functional VPN tunnel. Any unverified state must fail closed.
- **Full Egress Privacy Policy**: A privacy/VPN service for Lightning nodes must guarantee both inbound AND outbound clearnet encapsulation through the tunnel (true hybrid routing). Inbound-only tunneling leaks the operator's real residential IP via Lightning gossip, channel re-establishment, and peer ping/pong packets.

## umbrelOS LND Configuration Event Chain
- **Configuration Source of Truth**: In umbrelOS, `umbrel-lnd.conf` is an ephemeral file generated by a Node.js middleware service (`lightning_app_1`) from `lnd.conf`. Writing directly to `umbrel-lnd.conf` is futile as it is overwritten on boot. Always write to `lnd.conf`.
- **Sequential Restart Execution**:
  1. **Middleware First**: Restart `lightning_app_1` to ingest the configuration change.
  2. **Deterministic Delay**: Wait 3 seconds for configuration regeneration.
  3. **Daemon Last**: Restart `lightning_lnd_1` so it boots with the refreshed parameters.

## Code Quality & Diligence Standards
- **Strict Regex for Container Targeting**: Umbrel environments run multiple containers with similar substrings (e.g. `lightning_app_1` vs `lightning_app_proxy_1`). Always use anchored regex with digit suffixes: `r"^lightning[_-]app[_-]\d+$"`.
- **Atomic Configuration Swapping**: Write configuration changes to temporary files (with unique UUIDs) and execute `os.replace()`, followed by post-write byte-verification from disk before initiating service restarts.
- **Full-Spectrum Subsystem Auditing**: When altering routing tables, firewall rules, or VPN state, audit 100% of mutation and teardown pathways to prevent orphaned rules.

## Repository Discovery & Navigation
- `server/`: Python backend daemon (`app.py`), WireGuard manager, API endpoints, and system routing hooks.
- `web/`: Frontend React application for the Umbrel web dashboard.
- `tunnelsats/`: Umbrel App Store package manifests, `docker-compose.yml`, and container initialization scripts.
- `scripts/`: Host-level setup, migration, and teardown utilities.
- `docs/`: Historical implementation and authentication plans.
